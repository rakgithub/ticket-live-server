## Planning

- Assess complexity, ambiguity, and risk before deciding whether a plan is needed.
- For substantial features, significant refactoring, architecture changes, or
  complex cross-boundary fixes, use the `grill-me` skill.
- Inspect relevant code, contracts, and documentation before asking questions.
- Prefer existing patterns and infrastructure. Evaluate alternatives against
  requirements, reliability, operational complexity, and maintainability.
- Identify dependencies, edge cases, failure modes, and verification needs.
- For consequential changes, present the approach, affected modules, risks, and
  verification plan; obtain approval before implementation.
